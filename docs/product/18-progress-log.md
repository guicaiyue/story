## 3. 任务卡插件：改了什么、量到了什么

### 修掉的五处真实缺陷

| # | 缺陷 | 证据 | 状态 |
| --- | --- | --- | --- |
| 1 | 同一次工具调用**问人两遍**（guard 与 pre-execute 各建一条 ask） | `asks.json` 里 3 个问题 6 条，间隔 10–46 ms | 已修（`Ask.key` 去重） |
| 2 | blocking ask 在会话死后**永不结束** | 3 条 blocking 永远挂在待答 | 已修（6h 过期按默认收尾 + `ask:expired`） |
| 3 | 账本**原样留下生产口令** | 卡片 `c-mwbvil7x` 正文含明文口令 | 已修（落盘前脱敏，7 条测试） |
| 4 | destructive 动作的**默认答案是"继续"** | `rule:destructive-sql` 不匹配旧正则 → 默认放行删库 | 已修（按 effect 判定，5 条测试） |
| 5 | 拒绝后若 ask 没落地会**静默** | 只有一行 warn 可查 | 已修（零静默账本 + `/stats.silence`） |

### 现在的度量基线（`/stats`）

```
卡 86 张（open 3）｜人工动作 23 次｜ask 6 条：人答 0，默认收尾 6（autoRate = 1.0）
noise.cards.zeroActionRate ≈ 0.70（其中 79 张是 P1 授权反转之前的历史卡）
silence.unaccounted 目标恒为 0
```

**autoRate = 1.0 是最有用的一条**：闸门在工具调用前判断「要不要问人」，这个样本里
**六次全白问**。它直接支撑了 P4 的设计（把提问时机挪到回合末），也解释了为什么"安全网"
会变成"找事情"。
