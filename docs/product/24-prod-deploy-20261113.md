## 11. 把这一轮固化成的两条命令

上线当天是 11 个手敲动作，重做一次仍然会漏。已固化成脚本：

### `scripts/prod-deploy.sh`（生产运维，分段幂等）

```bash
./scripts/prod-deploy.sh status        # 只读：库 / 容器 / 域名
./scripts/prod-deploy.sh backup        # 带时间戳的 pg_dump
./scripts/prod-deploy.sh build         # server + admin 生产镜像
DATABASE_URL=… ./scripts/prod-deploy.sh migrate
STORY_APP_PASSWORD=… ./scripts/prod-deploy.sh grants
./scripts/prod-deploy.sh admin --phone <手机号>
./scripts/prod-deploy.sh up
./scripts/prod-deploy.sh smoke         # 读路径 + 后台登录/接口（不写库）
./scripts/prod-deploy.sh smoke --write # 再加游客注册 + TTS，结束自动清理
```

`status` / `smoke` 现在就能跑；本轮两条都跑过，输出见上。

### `apps/app/tool/build-release-apk.sh`（出包一条命令）

六段：查签名材料 → 查版号（不允许与已发布版本重号，`FORCE=1` 可强制）→ 跑测试 →
构建 → **自检产物**（`aapt2` 版号、`apksigner` 证书必须是 `CN=StoryNook`、三个 ABI 里
基址必须是正式域名且不含 `127.0.0.1:3000`）→ 归档 + sha256。

自检段是本轮踩坑换来的：
- `set -o pipefail` 下 `aapt2 … | head -1` 会因 SIGPIPE 让脚本以 **141** 退出（已改为先存变量）；
- SDK 位置要读 `android/local.properties` 的 `sdk.dir`，容器里 `ANDROID_HOME` 是空的。

实测：`FORCE=1 SKIP_TESTS=1 bash tool/build-release-apk.sh` → `EXIT=0`，产出 sha256 与本轮发布包一致
（`d7074dc8…`），说明脚本可重复复现同一个包。

## 12. 本轮踩到并修掉的两个脚本坑（留给下次）

| 坑 | 表现 | 修法 |
| --- | --- | --- |
| `preflight.sh` 在宿主上跑 | 服务端测试报 `Can't reach database server at story-dev-postgres:5432`，App 段 `SKIP 没有 flutter` —— 看起来像测试坏了，其实是跑错机器 | 脚本开头判定 `/.dockerenv`，不在容器里就打印正确命令并 `exit 2`（`HOST_OK=1` 可强行跑） |
| `set -o pipefail` + `aapt2 … \| head -1` | 出包脚本以 **141** 退出（SIGPIPE），且不打印任何错误 | 先存变量再取行；`apksigner` 同理 |

这两条都不是产品缺陷，是「工具在错的上下文里跑」——和插件那一轮修的「测试污染真实账本」是同一类问题：
**工具没有意识到自己在什么环境里**。
